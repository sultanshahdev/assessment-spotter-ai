# P07.4 evidence

All measurements are local; public demonstration city centers were verified with live TomTom v3 Suggest/Details. `inputs.json` holds public coordinates and the single departure used during this task. Update the departure before future live reproductions. No provider credentials, authenticated URLs, sensitive headers or raw live provider bodies are retained.

- `baseline.json`: initial short browser success and long-haul client deadline; early harness lacked completed backend timings for the cancelled request. `backend-baseline.json` retains separate direct measurements, including failures.
- `backend-after.json`: all six optimized cases, with every success and interrupted failure. `backend-after-repeat.json`: one predeclared final D25 repeat, successful; the earlier failure remains visible.
- `browser-after.json`: real A/D trip/weather responses with verified replayed location selection and background-only style. `browser-after-long-haul.png` is an early card-visible capture before map settlement; **use `browser-map-confirmation-long-haul.png` for the settled actual three geometries/checkpoints**. The separate map-confirmation trace waits for source completion and explicitly exercises Fit routes with reduced motion. Its routing/weather are real, its basemap is background-only.
- `dns.json`: separate system lookup observations; per-request DNS timings occur in after traces. Durations are milliseconds; `*_wire_bytes`, `*_attempt_count`, `checkpoint_count`, `weather_unique_locations`, `weather_http_calls` and `weather_batches` are counts/bytes even when older artifacts carry them inside `spans`. Current profiler sends those in `X-Profile-Counts`, timing durations in `Server-Timing`.
- `scale-controlled.json`: seven interleaved identical-geometry CPU pairs; primary scale comparison. Earlier `cpu-baseline.json`/`cpu-after.json` are uncontrolled exploratory observations, not the primary comparison. `weather-controlled.json` has seven fixture samples per size and explicitly simulated I/O, not actual weather. `offline-preparation.json` measures fixture window preparation+thread dispatch, not a live stage estimate.
- `autocomplete-baseline.json`/`autocomplete-after.json`: unavailable live suggestions; 25s sample values are the harness's option wait, not a provider latency. The early after recorder also includes one unlabelled style fetch; exclude it from autocomplete metrics. `autocomplete-deterministic.json` uses explicit synthetic suggestions and records two uncached requests/no cached revisit request. Cold startup contention is separated from configured debounce.
- `browser-results.json`: full deterministic suite report, 11 passed/3 opt-in live skipped. `browser-regression/` holds fresh changed deterministic artifacts from that run; prior P07.3 evidence was restored byte-for-byte. `real-basemap/` holds three changed captures from the passing external-style scenario; trip/weather fixtures are synthetic, not real provider results.
- `responsiveness.json`, `pending-analysis.png`, `deterministic-long-results.png`: synthetic 60000vertex stress case using actual MapLibre/WebGL. Two intentional analysis calls mean cancellation and replacement, not duplicate submissions. Panel timings include automation. No initial optional forecast HTTP.
- `security.json` and `screenshots.json`: final exact configured-secret scan and SHA256/PNG-size inventory. Visual inspection flags apply only to explicitly reviewed captures, not every regression image.

Single live samples do not establish production medians/p95 or isolate changes in provider traffic, forecast completeness, external DNS or server cache. No production speed guarantee is inferred from a faster later request. Full methodology and acceptance limits: [report](../p07-4-performance-report.md).

Final source browser regression was repeated after connection-error classification:11passed/3skipped. `responsiveness.json` is that final full-run observation; `responsiveness-focused.json` preserves the earlier focused panel-timing observation quoted in the report. `environment.json` and `source.json` record the local harness versions and intake-HEAD/final-runtime source hashes.
